# Kandela Kulture: Planning Strategy

*Pilot phase roadmap. This document lives alongside the manifesto — it describes how we get from where we are to where the manifesto says we're going.*

## Current state

**What exists:**
- Manifesto and philosophy (published)
- Core infrastructure: RSVP, consent, waitlist, admin tools, data retention
- Role definitions: Hearth, Keeper, Lamplighter, Flame, Partner
- Method framework: Spark → Pivot → Layer → Pass (named, not detailed)
- Single-chapter technical capacity (Worker deployment, D1 storage, WhatsApp integration)

**What's missing:**
- Role onboarding paths (how to actually become a Keeper/Lamplighter/Flame)
- Method depth (what Spark/Pivot/Layer/Pass look like in practice)
- Evidence of impact (lab notes, measurement data, cross-Hearth proof)
- Toolkit resources (session guides, facilitator playbooks)
- Hearth network layer (map, ceremony documentation, Passport functionality)

## Strategic principles

1. **Don't fake progress.** The manifesto promises transparency. We document what we *intend* and what we *have done*, never pretend to be farther along.

2. **Build infrastructure first.** Before we need to scale, build the systems that let us scale gracefully. Role signups, event feedback loops, data capture.

3. **Evidence fills the gaps.** Lab notes, facilitator guides, and toolkits come after the pilot, not before. Promise #6 binds us.

4. **Roles are open now.** People can express interest in Keepership/Lamplighting even if we don't have a formal process yet. Capture the intent.

5. **Method is a hypothesis.** The 4-step structure is a design, not a proven framework. Document it as such.

## Phase 1: Pilot foundation (Now)

**Goal:** Run the first gatherings, capture data, learn what works.

**Infrastructure to build now:**
- Role signup forms (Keeper, Lamplighter, Flame)
- Post-gathering feedback mechanism
- Basic measurement tracking (attendance, repeat rates, qualitative feedback)
- Method page depth (concrete examples of each step)

**What we do:**
- Run 3-5 gatherings with the same core group
- Test the Spark/Pivot/Layer/Pass structure
- Capture feedback after each session
- Document what actually happened vs. what we intended

**What we don't do:**
- Publish "lab notes" before we have data
- Create full facilitator toolkits before we know what works
- Claim Hearths in cities where we don't exist
- Pretend the Passport is functional when there's only one Hearth

## Phase 2: First Hearth stabilization (After pilot)

**Goal:** Make Nairobi a self-sustaining Hearth with clear paths to participation.

**Infrastructure to build:**
- Keeper onboarding process (selection, training, handoff)
- Lamplighter coordination system (shifts, roles, check-ins)
- Flame curation process (portfolio, collaboration, payment)
- Real lab notes (what worked, what didn't, what we changed)

**What we do:**
- Select and train 2-3 Keepers from the pilot group
- Establish a monthly gathering rhythm
- Publish first round of lab notes
- Create basic session guides (not yet "toolkits" — more like internal notes)

**What we don't do:**
- Expand to new cities until Nairobi is stable
- Launch the Passport cross-Hearth system until there's a second Hearth
- Certify skills (we remain a container, not a certifier)

## Phase 3: Second Hearth (Nairobi stable)

**Goal:** Test whether the model transfers. Light a second flame.

**Infrastructure to build:**
- Hearth application process
- Flame-passing ceremony (document and execute)
- Passport system (basic verification, host introductions)
- Multi-Hearth admin tools (data sharing, event coordination)

**What we do:**
- Invite applications for second Hearth
- Select and train a Keeper in the new city
- Run the flame-passing ceremony (document it as a real event)
- Launch Passport as a functional system

**What we don't do:**
- Rapid expansion before the second Hearth proves viability
- Franchise before we have evidence the model replicates

## Phase 4: Network growth (Multi-Hearth)

**Goal:** Scale cautiously with evidence at each step.

**Infrastructure to build:**
- Public Hearth map
- Full facilitator toolkit (now based on real experience)
- Accredited partner integration (for risky skills)
- Published measurement reports (connection metrics, not attendance)

**What we do:**
- Open Hearth applications quarterly, not continuously
- Publish annual connection reports
- Offer toolkit as open resource under appropriate license
- Integrate accredited providers for specific skills (first aid, etc.)

**What we don't do:**
- Optimize for growth over depth
- Promise Hearths where we can't support them
- Dilute the method to appeal to more people

## Defensible gaps to fill now (Prelaunch)

These don't require evidence — they're structural:

### 1. Role signup flows
- Add forms for Keeper, Lamplighter, Flame interest
- Store in D1, track separately from RSVPs
- Send acknowledgment (no promise of selection)
- Create admin view of role applicants

### 2. Method page depth
- Add concrete examples of Spark tasks (play-based cooperation)
- Add concrete examples of Pivot moves (face-to-face ↔ side-by-side)
- Add concrete examples of Layer additions (skills, services, making)
- Document Pass as "what participants take away" (conceptual)

### 3. Flame-passing ceremony
- Document the intended ceremony structure
- Frame as "This is how we intend to do it"
- Include the symbolic elements (candle, introduction, commitment)
- Link to Keeper/Passport pages

### 4. Pilot phase notice
- Add banner/notice clarifying pilot status
- Link to manifesto Promise #6 ("We say only what we know")
- Set expectation: real learnings come after gatherings happen

## Evidence gaps to fill later (Post-pilot)

These require real data:

### 1. Lab notes
- After each gathering: what we tried, what happened, what we'd change
- Publish both successes and failures
- Iterate the method based on evidence

### 2. Facilitator toolkit
- Session guides refined through actual use
- Timing notes, pivot prompts, layer options
- Material lists, space requirements

### 3. Hearth map
- Only show Hearths that actually exist
- Add "Coming soon" only when applications are in process
- Never invent presence

### 4. Measurement reports
- Connection metrics: how many contexts pairs share
- Continuity: do groups keep going without us?
- Counterfactual: would this have happened without us?

## Success metrics

**Pilot success:**
- 70%+ repeat attendance across 3-5 gatherings
- Qualitative feedback indicating new connections formed
- At least 2 people express interest in Keepership
- Clear documentation of what worked/what didn't

**Hearth stability:**
- Self-sustaining monthly rhythm without founder presence
- Keeper successfully hosts 3 consecutive gatherings
- Lamplighter team in place (3+ active volunteers)
- Flame pipeline (2+ artists/creators engaged)

**Network readiness:**
- Nairobi Hearth meets stability criteria for 6 months
- At least 5 qualified Hearth applications
- Flame-passing ceremony executed and documented
- Passport system tested with trial travelers

## Risks and mitigation

**Risk: Pilot doesn't produce repeat attendees**
- Mitigation: Document why, iterate the method, don't force growth

**Risk: No one applies for Keepership**
- Mitigation: Explicitly invite from pilot group, lower barrier for first cohort

**Risk: Second Hearth fails**
- Mitigation: Pause expansion, focus on stabilizing Nairobi, don't rush

**Risk: Method doesn't transfer across contexts**
- Mitigation: Adapt for context, document adaptations, keep core principles

**Risk: Burnout of early volunteers**
- Mitigation: Clear role boundaries, rotation schedules, recognition

## Timeline (Indicative, not rigid)

- **Month 1-3:** Pilot gatherings, role signups, feedback capture
- **Month 4-6:** First Hearth stabilization, lab notes v1
- **Month 7-9:** Second Hearth planning, flame-passing ceremony
- **Month 10-12:** Second Hearth launch, Passport beta
- **Year 2:** Cautious network growth based on evidence
